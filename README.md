# 最長片道切符の問題

このプログラムは、鉄道路線図をグラフと見立てて、一番長い一筆書きの経路（最長片道きっぷ）を見つけ出すものです。

## このプログラムについて

- **無向グラフ**: 駅と駅がつながっている場合、どちらの方向からでも通れるものとして扱います。
- **同じ道の往復は禁止**: `A駅 → B駅 → A駅` のように、同じ区間をすぐに折り返す経路は計算に含めない。ただし、`A駅 → B駅 → C駅 → A駅` のような、3つ以上の駅をめぐる周回ルート（閉路）はOKです。

## こだわった点

- 42Tokyoの独特のコーディング規則を部分的に採用し、各関数は25行制限を課しています。リファクタリングしやすくすることと可読性向上のためです。
- 引数の数も3つまでにしています。上記と同じ理由です。

## 使い方

### 実行方法

ターミナルで、以下のコマンドを入力。
`input.txt` の部分には、路線データのファイル名を指定する。
テスト用ファイルはtest/配下に格納しています。

```bash
python3 graph_solution.py < input.txt
```

### 入力データの形式

路線データのファイルは、以下のような形式で作成します。

`駅Aの番号, 駅Bの番号, 2駅間の距離`

カンマで区切り、1行に1つの路線情報を書きます。

**入力例 (`input.txt`)**
```
1, 2, 8.54
2, 3, 3.11
4, 1, 1.4
3, 1, 2.19
3, 4, 4
```

### 出力結果

計算結果として、最も長くなる経路の駅番号を順番に出力します。

**出力例**
```
2
1
4
3
2
```
この例は、`駅2 → 駅1 → 駅4 → 駅3 → 駅2` という順番でめぐるのが一番長い、ということを示しています。

## テスト用のデータ

`test/` フォルダの中に、いくつかテスト用の入力ファイルを用意しています。

- `test1.txt`: 基本的な閉路を含むデータ
- `test2.txt`: 一本道のデータ
- `test3.txt`: 少し複雑なグラフ
- `test4.txt`: 全ての駅がつながっているグラフ

試すには、以下のように実行。

```bash
# test1.txt を使って試す
python3 graph_solution.py < test/test1.txt
```

## 注意点

- この計算方法は、駅の数が多くなると（20駅を超えるくらいから）非常に時間がかかるようになります。
- 大規模な路線網で試す場合は、もっと効率的な別のアルゴリズ厶を検討する必要がありました..
